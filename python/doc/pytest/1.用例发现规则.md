# pytest 用例发现规则详解

pytest 有非常智能的测试用例发现规则，了解这些规则能帮助你更好地组织测试代码。

## 一、默认发现规则

### 1. **文件命名规则**
pytest 会查找以下文件：
- `test_*.py`：以 `test_` 开头的 Python 文件
- `*_test.py`：以 `_test` 结尾的 Python 文件

**示例：**
```
✅ 会被发现的文件：
test_user.py
test_database.py
user_test.py
database_test.py

❌ 不会被发现的文件：
user.py           # 没有 test_ 或 _test
testdata.py       # test 在中间
test.py           # 只有 test，没有后续字符
tests.py          # test 后面是 s，不是下划线
```

### 2. **目录命名规则**
pytest 会递归查找所有子目录，不需要特殊命名。

**示例项目结构：**
```
project/
├── src/
├── tests/                    # 传统测试目录
│   ├── test_core.py
│   └── test_utils.py
├── unit_tests/              # 任何目录名都可以
│   └── test_auth.py
└── integration_test/        # 可以包含 test
    └── test_api.py
```

## 二、测试函数发现规则

### 1. **函数命名规则**
pytest 会查找以下函数：
- `test_*`：以 `test_` 开头的函数

**示例：**
```python
# ✅ 会被发现的测试函数
def test_add():                  # 正确
def test_user_creation():        # 正确
def test_database_connection():  # 正确

# ❌ 不会被发现的测试函数
def add_test():                  # test 在结尾
def TestAddition():              # test 在开头，但大写了
def test():                      # 只有 test，没有后续字符
def Testing():                   # 包含 test，但不是以 test_ 开头
```

### 2. **测试类命名规则**
pytest 会查找以下类：
- `Test*`：以 `Test` 开头的类（注意：T 大写）
- 类中的测试方法：以 `test_` 开头的方法

**示例：**
```python
# ✅ 会被发现的测试类
class TestUser:                    # 正确：Test 开头
    def test_create_user(self):    # 正确：test_ 开头
        pass
    
    def test_delete_user(self):
        pass

class TestDatabaseOperations:      # 正确
    def test_connect(self):
        pass

# ❌ 不会被发现的类
class UserTest:                    # Test 在结尾
    def test_something(self):      # 这个方法会被发现！
        pass

class testDatabase:                # test 小写开头
    def test_connect(self):        # 这个方法不会被发现！
        pass
```

## 三、测试方法发现规则

### 1. **类中测试方法**
```python
class TestCalculator:
    # ❌ 不允许有此函数
    def __init__(self):
        pass
    
    # ✅ 会被发现的方法
    def test_add(self):            # test_ 开头
        pass
    
    def test_multiply(self):
        pass
    
    # ❌ 不会被发现的方法
    def add_test(self):            # test 在结尾
        def test_helper(self):     # 嵌套函数
            pass
        setup(self):               # 不以 test_ 开头
```

### 2. **特殊方法**
```python
class TestDatabase:
    # pytest 生命周期方法
    def setup_method(self):
        """每个测试方法前执行"""
    
    def teardown_method(self):
        """每个测试方法后执行"""
    
    def setup_class(cls):
        """整个类测试前执行"""
    
    def teardown_class(cls):
        """整个类测试后执行"""
    
    # 这些不会被当作测试用例
```

## 四、测试模块发现规则

### 1. **模块中的测试函数**
```python
# test_math.py
import math

# ✅ 测试函数（会被发现）
def test_addition():
    assert 1 + 1 == 2

def test_subtraction():
    assert 3 - 1 == 2

# ❌ 普通函数（不会被发现）
def helper_function():
    return 42

def setup():
    """这不是测试用例"""
    return True

# ✅ 测试类（会被发现）
class TestMath:
    def test_multiply(self):
        assert 2 * 3 == 6
```

### 2. **模块级别的fixture**
```python
# test_database.py
import pytest

@pytest.fixture
def db_connection():
    """这不会被认为是测试用例"""
    return create_connection()

def test_query(db_connection):
    """这是测试用例"""
    result = db_connection.query("SELECT 1")
    assert result == 1
```

## 六、conftest.py 的特殊规则

### 1. **conftest.py 的作用**
- 存放共享的fixture
- 每个目录都可以有一个 conftest.py
- 作用域：当前目录和所有子目录

### 2. **目录结构示例**
```
project/
├── conftest.py                    # 项目级fixture
├── tests/
│   ├── conftest.py               # tests目录级fixture
│   ├── unit/
│   │   ├── conftest.py          # unit目录级fixture
│   │   ├── test_auth.py
│   │   └── test_db.py
│   └── integration/
│       ├── conftest.py          # integration目录级fixture
│       └── test_api.py
```

## 七、自定义发现规则

### 1. **修改 pytest.ini**
```ini
# pytest.ini
[pytest]
# 修改测试文件模式
python_files = test_*.py *_test.py check_*.py

# 修改测试函数模式
python_functions = test_* check_*

# 修改测试类模式
python_classes = Test* Check*
```

### 2. **pyproject.toml**
```toml
# pyproject.toml
[tool.pytest.ini_options]
python_files = ["test_*.py", "*_test.py", "check_*.py"]
python_functions = ["test_*", "check_*"]
python_classes = ["Test*", "Check*"]
```

pytest tests/test_calculator.py

# 4. 查找特定测试函数
pytest tests/test_calculator.py::test_add

pytest tests/test_user.py::TestUser::test_create

## 九、特殊情况的处理

### 1. **__init__.py 文件**
```python
# tests/__init__.py
# 即使有 __init__.py，pytest 仍然会查找其中的测试用例

def test_in_init():
    """这个会被发现！"""
    assert True

class TestInInit:
    def test_method(self):
        """这个也会被发现！"""
        assert True
```

### 2. **隐藏文件和目录**
pytest 默认会忽略：
- 以 `.` 开头的文件和目录
- 以 `_` 开头的目录（但 `_` 开头的文件会被查找）

```
project/
├── .pytest_cache/           # 被忽略
├── __pycache__/             # 被忽略
├── _build/                  # 被忽略（目录）
├── _test_private.py         # ✅ 会被查找（文件）
├── test_public.py           # ✅ 会被查找
└── .test_hidden.py          # ❌ 被忽略
```

### 3. **测试发现配置示例**
```ini
# pytest.ini
[pytest]
# 测试文件模式
python_files = 
    test_*.py
    *_test.py
    spec_*.py
    *_spec.py

# 测试函数模式
python_functions = 
    test_*
    should_*
    check_*

# 测试类模式
python_classes = 
    Test*
    Spec*
    Check*

# 忽略的目录
norecursedirs = 
    .git
    .venv
    node_modules
    build
    dist
    __pycache__

# 自定义测试收集
testpaths = 
    tests
    integration_tests
```

## 十、测试发现调试

### 1. **显示收集的测试**
```bash
# 只收集测试，不运行
pytest --collect-only

# 显示详细收集信息
pytest --collect-only -v

# 显示收集到的测试项
pytest --collect-only --tb=no
```

**输出示例：**
```
<Module test_calculator.py>
  <Function test_add>
  <Function test_subtract>
<Module test_user.py>
  <Class TestUser>
    <Function test_create_user>
    <Function test_delete_user>
```

### 2. **调试测试发现**
```bash
# 显示pytest如何查找测试
pytest --debug

# 显示配置
pytest --version
```

### 3. **排除特定测试**
```bash
# 排除特定目录
pytest --ignore=tests/legacy/

# 排除特定文件
pytest --ignore=tests/test_deprecated.py

# 通过名称排除
pytest -k "not slow"
```

## 十一、常见问题解决

### 问题1：测试没有被发现
**原因：**
- 文件名不符合规则
- 函数名不符合规则
- 类名不符合规则

**解决：**
```bash
# 查看收集到的测试
pytest --collect-only

# 检查命名规则
# 文件：test_*.py 或 *_test.py
# 函数：test_*
# 类：Test*
```

### 问题2：导入错误
**原因：**
- Python路径问题
- 模块未安装

**解决：**
```bash
# 设置PYTHONPATH
PYTHONPATH=/path/to/src pytest

# 或使用 -c 参数
pytest --import-mode=importlib
```

### 问题3：测试执行顺序
```bash
# 随机执行顺序
pytest --random-order

# 按字母顺序
pytest --collect-only -q | sort

# 按模块分组
pytest --collect-only --tb=no | grep "Module"
```

## 十二、最佳实践

### 1. **推荐的命名规范**
```python
# 文件命名
test_module.py          # 推荐
module_test.py          # 可以，但不常见
module_spec.py          # 如果配置了 python_files

# 函数命名
def test_function():    # 推荐
def should_do_something():  # 如果配置了 python_functions

# 类命名
class TestFeature:      # 推荐（T大写）
class FeatureTest:      # 避免（测试方法能被发现，但类本身不会）
```

### 2. **目录结构建议**
```
# 推荐结构
project/
├── src/                # 源代码
│   └── myapp/
├── tests/              # 测试代码
│   ├── unit/          # 单元测试
│   ├── integration/   # 集成测试
│   └── conftest.py    # 共享fixture
├── pyproject.toml     # 项目配置
└── README.md
```

### 3. **配置建议**
```ini
# pytest.ini 示例
[pytest]
addopts = 
    -v
    --tb=short
    --strict-markers
    --strict-config
    
testpaths = 
    tests
    
python_files = 
    test_*.py
    *_test.py
    
python_functions = 
    test_*
    
python_classes = 
    Test*
    
markers = 
    slow: marks tests as slow
    integration: marks tests as integration tests
    smoke: marks tests as smoke tests
```

## 十三、总结

1. **文件发现**：查找 `test_*.py` 和 `*_test.py`
2. **函数发现**：查找 `test_*` 函数
3. **类发现**：查找 `Test*` 类中的 `test_*` 方法（类没有 `__init__` 函数）
4. **递归查找**：pytest 会递归查找所有子目录(venv 和 . 开头的除外)
5. **配置灵活**：可以通过配置文件自定义规则
6. **调试方便**：使用 `--collect-only` 查看发现结果

掌握这些规则，你就能：
- 正确命名和组织测试代码
- 理解为什么某些测试没有被发现
- 自定义测试发现行为
- 调试测试发现问题
